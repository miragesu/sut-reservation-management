# Proposed HTTP, WebSocket and broker contracts

Design contract version `console.v1`; no route is implemented. Keep existing REST/HTML coordination contracts intact. All Console responses no-store; no credentials in URL, query, cookie, redirects, exception echo, metrics labels or traces. All mutations require current active login, completed password change, exact Origin and x-csrf-token. IDs never confer authorization. Permissions are rechecked on commit/redemption, not just preflight. Feature OFF rejects Console connects/management and hides links; existing site remains available.

## HTTP resources

Prefix `/api/v1/console`. JSON field allowlists forbid user_id injection except explicit admin grant subject. Version uses integer `expected_version`; If-Match may mirror it but cannot conflict. UTC timestamps serialized with Z. Unrecognized fields rejected. Lists paginated with page_size<=100.

Grant lists are admin-visible through authorized `/grants?sut_id=...`; ordinary RD receives only own effective grant, not peers' reasons. API provides no secret GET/decrypt/download, tmux session creation/list inventory, generic command, arbitrary target argument, writer takeover, recording, replay, restore-history or session-admin-kill routes. HTML `/suts/{id}/console` standalone and `/my-console-sessions` require login; read-only/denied users can view guidance but no illicit connect. Existing SUT Detail provides mapping/history and Open Console links only when enabled.

For initial Client onboarding, `/host-trust/accept` records only a transient comparison proof in the validation flow; durable initial trust is committed with the successfully authenticated Client create. It must not insert orphan trust/Client/credential rows when onboarding fails. Replacement trust on an existing Client is a distinct durable operation with its own confirmation and revocation, as required by Q74. Safe failure-audit metadata may remain in either case.

Errors use `{detail:{code,message,retryable,request_id,context}}` on Console endpoints only. Safe context may contain current_version, authorized conflict SUT identity, quota and impact summaries; never secret payload, raw SSH exception or infrastructure-deny list. Codes: 401 auth_required/auth_expired; 403 forbidden/password_change_required/origin_rejected; 404 feature_disabled/not_found; 409 version_conflict/confirmation_required/mapping_pair_in_use/client_ip_in_use/trust_changed/validation_stale/grant_conflict; 422 invalid_input/target_denied; 429 session_quota/inflight_limit (NOT password rolling lockout); 502 ssh_auth_failed/tmux_missing; 504 ssh_connect_timeout; 503 broker_unavailable. Failed candidate validation preserves old live state. Trust required is a structured challenge, not an automatic accept.

Proposed tmux syntax: 1–128 ASCII `[A-Za-z0-9_][A-Za-z0-9_-]*`, exact case; reject spaces, colon, period, prefix `-`, format expansions, controls and shell metacharacters. This narrows valid tmux naming for injection safety and is engineering assumption H4, requiring compatibility review before coding. Never interpolate even validated string into a shell. Client usernames capped128, credential upload proposed64KiB; validate without echo. Optional reasons <=1000 characters, notes <=4000; do not require a reason where owner permits blank.

## WebSocket state machine and frames

Path `/ws/v1/console`, subprotocol `console.v1`; no ticket or credential query parameters. Before upgrade check exact Origin, active login/must-change gate, feature and HTTP opt-in. Upgrade uses a short first-frame timer (proposed5s); first JSON frame `{"type":"authenticate","ticket":"opaque","tab_nonce":"opaque","generation":1}`. Atomically redeem once against same login, origin, tab, quota row, mapping and epochs. No SSH/terminal input before redemption. Reject missing/null/foreign Origin, replay, wrong tab, expired ticket, old login or stale generation. Cookie alone cannot start SSH. WS access logs omit sensitive frames; forbid frame logging.

Server then emits `state` with Not Connected / Connecting / Connected / Reconnecting / Disconnected / Failed, effective read/write mode and safe reason. For BMC only, `credentials_required {flow_id,attempts_remaining}` follows trusted-key validation; client sends `bmc_auth {username,password}` once per attempt. Values are volatile and cleared after attempt; third failure ends flow, no automatic retry. Reconnect must prompt anew when SSH authentication is needed. UART never asks RD for Client secret. Unknown/changed trust emits challenge metadata and blocks authentication until HTTP trust acceptance; a committed trust replacement revokes existing affected links and old flow versions, requiring fresh manual Connect.

After Connected:

| Direction / frame | Contract |
|---|---|
| Browser JSON `input {seq,data_b64}` | Literal bytes, proposed max8KiB decoded/frame; only Connected writable. Monotonic seq per generation, duplicates/out-of-order rejected. No command interpreter. Embedded controls still subject to helper confinement. No queued input across disconnect |
| Browser JSON `paste {seq,data_b64,multiline_confirmed}` | Single line direct; CR/LF normalized for line counting without logging, preview/count in browser for >1 line. Reject multiline paste without explicit flag; flag is UX acknowledgement, not proof against a malicious writer who can type the same commands. NUL/unsafe clipboard controls rejected with explanation rather than silently executed. Read-only/disconnected rejected |
| Browser JSON `send_key {seq,key}` | Enum esc/tab/ctrl_c/ctrl_d/ctrl_z; one byte/control sequence once; same server rights as input, no advanced hardware key |
| Browser JSON `resize {cols,rows}` | Integers proposed2..500 cols,1..300 rows; coalesce <=10/s; same session only; PTY propagation, never tmux global window-size changes. Read-only geometry must not become an input bypass |
| Browser JSON `disconnect` | Immediate current flow cancellation; no extra confirmation or auto retry |
| Server binary output | Raw terminal bytes, proposed <=32KiB/frame; decoder handles split UTF-8/ANSI; render through xterm.js only, not DOM HTML |
| Server JSON `participants` | Distinct RD names/modes and tab counts scoped to endpoint; shared UART warning if >=2 RD |
| Server JSON `input_ack {seq,stage:"broker_written"}` | Means local broker wrote bytes, not remote execution/success; do not replay absent ack |
| Server JSON `revoked {code,manual_reconnect_required:true}` | Clear bounded pending bytes, stop retries, close; code mapping_changed/client_disabled/credential_changed/host_key_changed/auth_revoked/feature_disabled |
| Server JSON `mode_changed` / `error` / `state` | Allowlisted codes/messages, no stack traces. A write-to-read downgrade discards pending writes and announces mode |

Reject unknown types, unexpected binary browser frames, oversized JSON/base64, auth after Connected and credentials outside BMC auth state. Proposed total text frame64KiB, per-session output queue1MiB, input queue64KiB and input throughput64KiB/s with bounded burst; these are engineering budgets, not new session-policy knobs. On slow consumer pause SSH read within bounded flow control, then close with `slow_consumer` if deadline exceeded; no disk spooling or unlimited RAM. Bound terminal line size/total memory as well as 10k line count. No automatic clipboard writes or automatic terminal responses from read-only xterm.

Close statuses proposed:1000 intentional/normal;1008 policy/read-only/protocol violation;1009 too large;1011 broker/internal sanitized failure; application4401 login expiry,4403 policy revocation,4409 endpoint/trust invalidation,4429 quota. A close code does not replace explanatory safe state. Cleanup is idempotent on timeout, TCP loss, exception or tab close; do not rely on beforeunload to reclaim slots. No keyboard-idle timer. Browser receives uninterrupted output while authorization remains valid, including background tabs as browser permits.

## Gateway ↔ broker RPC

Private length-prefixed, versioned structured messages with authenticated boot capability and request ID: probe_key(target/version), validate_client(candidate handle), encrypt_candidate/commit_candidate, open(session/generation/target/key/credential-ref/mode/lease), input, resize, fence(scope/epoch), close, lease_refresh and rotation operations. Gateway never receives decrypted Client secret. Broker checks bounded types, canonical target restrictions, pinned key and generation/lease before network or byte writes; no raw shell/exec/forward request. Candidate handles are user/login/proposal bound, expire and cannot reveal secret. Each open is single session/transport; closed/fenced generations cannot resume.

Fence acknowledge means no new queued writes can reach SSH for that scope; already-sent bytes are outside rollback. Broker control-channel loss pauses then expires all leases; generation/boot reconciliation closes orphans after restart. Durable revocations in SQLite replay before new admission. Broker has no direct SQLite access and cannot claim a successful security change before gateway transaction commits. Output metadata includes session/generation only; terminal bytes never enter audit or RPC logs.
